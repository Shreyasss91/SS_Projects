# 🛠️ Git Bash Cheat Sheet: Workspace Setup & File Comparison

## 1. Initial Workspace Setup & Identity Configuration
Use these commands when you are setting up a completely new project environment or configuring Git on a fresh machine.

```bash
# Move into the master directory where you store your AI code projects
cd "E:\Downloads\AI Codes"

# Create a brand new project folder specifically for testing file differences
mkdir git_diff

# Step into the newly created project folder
cd git_diff

# Initialize a blank local Git repository (creates the hidden .git metadata folder)
git init

# Rename your primary workspace branch to 'main' (aligns with modern GitHub standards)
git branch -M main

# Set your global email identity so Git can attribute project changes to you
git config --global user.email "shreyas.ss91@gmail.com"

# Set your global display name for your commit author logs
git config --global user.name "Shreyas S S"
```

## 2. Tracking, Staging, and Saving Files
When you drop files manually into your project directory using Windows File Explorer,
Git notices them but marks them as **untracked**. Follow these steps to save them
into Git’s permanent memory.

```bash
# Check the working tree status to see which files are new, modified, or untracked
git status

# Add a specific file to the staging area (tells Git to include this file in the next snapshot)
git add filename.py

The git add . command stages all modified, new (untracked), and deleted files in the current directory and its subdirectories.
If you ran git add . by mistake and want to unstage your files without losing your actual code edits, run
git reset

# Permanently save your staged snapshot to the local repository history with a message
git commit -m "Initial version"
```

## 3. Comparing Local Files (Direct File Diffing)
Use these variations to track modifications between two files residing within the exact same directory.

### Standard File Diff (Opens Interactive Viewer)
* **Why use `--no-index`?** This flag forces Git to compare the two physical files directly on your hard drive, bypassing the Git staging area/commit history completely. It works even if the files are entirely untracked.
git diff --no-index old.py new.py

# Print the entire file comparison directly to the console timeline without stopping (skips the viewer)
git --no-pager diff --no-index old.py new.py

# Stream the entire diff directly into a standalone text file (creates or overwrites gitdiff.txt)
git --no-pager diff --no-index old.py new.py > gitdiff.txt



### Read Terminal Output Map
* 🔴 **`-` Lines (Red / Starting with minus):** Content that exists only in the first file (`old.py`) and was removed or modified.
* 🟢 **`+` Lines (Green / Starting with plus):** Content that exists only in the second file (`new.py`) and represents newly added code.

### Interactive View Navigation Controls
If your file is long, Git drops you into a screen pager utility (`less`). Use these hardware keys to navigate:
* **`Enter`** or **`Down Arrow`**: Scroll down by a single line.
* **`Spacebar`** or **`Page Down`**: Scroll down by a full display screen.
* **`Up Arrow`** or **`Page Up`**: Scroll backward up through your file.
* **`q`**: Quits/exits the viewer instantly and restores your normal terminal prompt (`$`).

## 4. Advanced Diff Variations & File Exporting
These options let you modify how changes are evaluated or dump the results directly out of your terminal screen.

# Display a high-level file summary showing lines added/deleted instead of line-by-line code
git diff --stat file1.py file2.py

# Ignore pure white space changes, indentation shifts, or empty line breaks when comparing code
git diff -w file1.py file2.py

To write a 100-line git commit message, you must use a text editor rather than the standard -m flag
Run the commit command without the -m flag. This action opens your default system text editor (usually Vim or Nano)
The first line is your short summary.  --> the subject
Leave the second line completely blank. --> to separate the title from the body.
Start your 100-line detailed explanation on line 3. --> the body

Change Your Git Editor
To use VS Code: git config --global core.editor "code --wait"
To use Notepad (Windows): git config --global core.editor "notepad"

The File Method (Alternative)

how to view this long message cleanly in your terminal history using git log
git log

View only the most recent long message
git log -1

See which files changed along with the long message
git log -1 --stat

If you want to indent the long text so it reads like a clean document, format the output directly:
git log --format=format:"%C(yellow)%h%C(reset) %s%n%n%w(80,4,4)%b"
	%h %s: Shows the short commit ID and the title.
	%w(80,4,4)%b: Wraps your 100-line body (%b) at 80 characters and indents it by 4 spaces for readability.
